# СЛОЙ — архитектура (черновик)

```
Telegram-клиент ── Mini App (этот репозиторий: index.html, app.js …)
       │                         │  fetch /api/*  (initData → проверка подписи на бэкенде)
       │                         ▼
       └── Business-подключение ─► Бот (Bot API) ─► Бэкенд ─► БД (сообщения, память, подписки)
              business_message                          └─► LLM-анализ (RADAR/REPLY/RECAP)
```

## Что уже есть
- Mini App (`web/`): Страница / RADAR / Разбор / Память / Слои / Билет, пустой первый день, демо-режим вне Telegram.
- Бэкенд (`server/`): вебхук с секретом, приём Business-сообщений, разбор, лента, ответ от имени пользователя, счета в Stars, продление билета, стирание памяти. Покрыто тестами.
- `analyze.js` — правила, не LLM: ловит сроки («до 18:00», «до пятницы»), просьбы, личные вопросы, рекламу.

## Что осталось
1. Задеплоить на HTTPS-хостинг, пройти шаги из README с реальным ботом (до этого Telegram-часть проверена только тестами с подставным API).
2. Заменить правила в `analyze.js` на LLM (тот же формат результата); MEMORY сейчас не наполняется автоматически — нужны извлечение фактов и экран правки.
3. RECAP (вечерняя сводка) — планировщик + сообщение бота; AUTOMATION — правила «если → то».
4. Лимиты тарифов (`plans.js` хранит число чатов, но нигде не применяется).
5. Группы: через права админа и `/recap` — отдельная задача.

## Открытые вопросы (не проверено)
- Нужен ли Telegram Premium для Business-подключения (источники противоречат).
- Могут ли пользователи из России купить Stars. От этого зависит выбор способа оплаты.
- Автопродление подписки на бот через Stars — не подтверждено; в дизайне «билет на 30 дней».
- Условия для разработчиков Telegram (telegram.org/tos/bot-developers) и 152-ФЗ — прочитать/юрист.
